# 차곡 기능 명세서 v0.4 (앱 전체)

Nov 5, 2026 · @June

안드로이드 담당이 이 문서만 보고 11/7부터 구현할 수 있게, 기능마다 입력·처리·출력·예외·수용 기준(AC)을 적어요. v0.4는 v0.3 합본(11/5, 효성)을 본문으로, 검토에서 나온 오류 3개·충돌 4쌍·빈칸 6개를 고친 판이에요. 이후 기준본은 이 문서이고 v0.3은 폐기해요.

## 1. 범위와 기준, 바뀐 점

- **기준 문서:** 기능·화면·문구·일정은 차곡 PRD v1.2, 수식·API 계약·fixture·검증은 [서버·추정 엔진 PRD v0.1](https://claude.ai/artifact/M6ZJW24C9XCv86MYzmskcf). 차량 신호의 API·단위·권한은 8절 신호 표가 우선이에요. 엔진 PRD에 반영할 변경은 11절 끝에 모았어요.
- **범위:** MVP 9개(F1·F2·F3·F5·F8·F9·F10·F11·F17) + S1 설정 + X1 주행 중 숨김 + X2 공통 예외. P2(F12·F13·F14·F18)는 제약만.
- **표기:** `AC-F5-3`, `[미확인]`, `[11/5]` 안건 확정 전제, `[11/7 결정]`, `[효성 확인]`, `D1~D6`(엔진 PRD 7절), `T1~T10`(엔진 PRD 8절).
- **전제:** 11/5 안건 3개 중 ① 잔고·범위·정산 로컬 계산, ② 주행가능거리 1순위 AAOS `RANGE_REMAINING`, ③ 실제 카테고리(Lifestyle 등) + `distractionOptimized` 미선언으로 확정된다고 보고 썼어요.

## 3. 화면 전이

&#91;embedded content: 화면 전이 · 정차 화면 8개, 주행 상태 1개\]

앱을 열 때 직전 스냅샷보다 주행거리가 늘었으면 정산 카드를 먼저 띄우고, 아니면 바로 홈이에요. 진행 중인 `pending` 여행이 있으면 정산을 건너뛰고 도착 처리(F17)에 맡겨요. 한 장은 범위의 "한 장 뽑기", 홈의 오늘의 한 곳, 충전 종료(F9, 범위를 건너뛰어) 세 길로 열려요. 교체 3회째는 범위 화면으로 돌아가요. 휴게소 추천 화면은 없고, 주행 중 화면은 1차에 없어서 영상 목업으로만 다뤄요.

## 4. F1 잔고 · F2 범위 · F3 테마

### F1 잔고 카드 (홈)

| 항목 | 명세 |
| --- | --- |
| 트리거 | 홈 진입, 설정 변경 후 복귀, SOC·연료 %·`RANGE_REMAINING` 리스너 |
| 입력 | 주행가능거리 AAOS `RANGE_REMAINING`(m) · SOC `EvBattery.getEvBatteryStateOfCharge`(%) / 연료 % `Fuel.getFuelPercent`(에뮬은 설정 모의 값) · 용량 AAOS `INFO_EV_BATTERY_CAPACITY`(Wh) → 없으면 차종 표 · 연비 `Fuel.getCumulativeFuelEconomy`(L/100km) / 전비 `EvBattery.getCumulativeEvEfficiency`(km/kWh) → 없으면 차종 표 · 단가(설정: 최근 단가 > 주변 평균 > 앱 내장 기본값) |
| 처리 | 잔고 km = `RANGE_REMAINING` ÷ 1000. 0 또는 없음이면 잔량 × 용량 × 연비. 내연 연비는 100 ÷ (L/100km)로 km/L 환산. 차종 표 값을 쓸 때만 실연비 = 공인 × 0.85. 잔고 원 = 잔량 × 용량 × 단가(천 원 반올림). 두 km가 30% 이상 다르면 로그 `range_gap` |
| 출력 | "탱크에 3만 8천 원어치 · 약 420km"(EV "배터리에"). 단가 출처 작게 |
| 예외 | 둘 다 없음 → "차량 정보를 읽는 중" + 설정 이동 |

- AC-F1-1: D1(SOC 80%, 77.4kWh, 300원)에서 "약 1만 9천 원어치"(61.92kWh × 300 = 18,576 → 반올림), km는 콘솔 Remaining Range ÷ 1000
- AC-F1-2: Remaining Range 0 → 조립식(61.92 × 6.2 × 0.85 ≈ 326km) + 로그 `range_fallback`
- AC-F1-3: 설정 단가 변경 시 홈 복귀 즉시 금액 변경
- AC-F1-4: 내연 실차에서 연비 8.0(L/100km) → 12.5km/L로 계산(단위 테스트)
- AC-F1-5: 콘솔 용량을 60(kWh)으로 바꾸고 홈에 다시 들어오면, `INFO_EV_BATTERY_CAPACITY` 60,000Wh 기준으로 잔고 원이 바뀌어요(차종 표보다 우선)
- AC-F1-6: 홈이 보이는 동안 콘솔 SOC를 바꾸면 2초 안에 잔고 원이 바뀌어요(리스너)

### F2 범위 설정

| 항목 | 명세 |
| --- | --- |
| 트리거 | 홈 "갈 곳 보기", 교체 3회째 "테마를 바꿔 볼까요?" |
| 입력 | F1 잔고 km, 프리셋(추가 0 / +1만 / +3만, 기본 0), 당일/1박(기본 당일), 인원(착석 자동, 수정 가능), 테마 0\~2 |
| 처리 | 안전 여유 = max(50km, 잔고 km × 15%). 반경 = (잔고 km − 여유 + 추가금 ÷ 단가 × 연비) ÷ 2 ÷ 1.3. 1박은 왕복에서 30km 추가 차감. `RANGE_REMAINING`이 예비분을 이미 뺀 값인지 `[미확인]` → 확인 전까지 여유 그대로 |
| 출력 | 프리셋 칩에 반경("추가 0원 · 약 106km"), 인원·테마 칩, "한 장 뽑기" |
| 예외 | 잔고 km < 여유 → 추가 0원 비활성 + "추가 0원 범위가 없어요. +1만 원부터 볼게요", 기본 +1만 |

- AC-F2-1: D1에서 추가 0원 반경 약 106km(±2km), D2에서 약 36km. 콘솔 Remaining Range를 D1 326,000m · D2 143,000m로 SOC와 함께 맞춰요
- AC-F2-2: 잔고 40km → 추가 0원 비활성, 안내 문구, +1만 자동
- AC-F2-3: 1박은 당일 대비 약 11.5km 작아요

### F10 정산 카드 (앱 열 때)

| 항목 | 명세 |
| --- | --- |
| 트리거 | 앱 실행 또는 다른 앱에서 복귀(기어 P). 시동 자동 실행은 문서 없음 → 쓰지 않음. 직전 스냅샷 없으면 저장만. **진행 중 `pending` 여행이 있으면 건너뛰고 도착 처리(F17)에 맡김** |

- AC-F10-2: Δodo = 0이면 카드 없이 홈
- AC-F10-3: T1\~T10 단위 테스트 통과
- AC-F10-4: 재시작 후 스냅샷 유지
- AC-F10-5: 콘솔 `PUT /vehicle/odometer?traveled_distance_km=`로 132km 올리고 앱을 다시 열면 카드가 떠요(콘솔은 줄일 수 없으니 리허설 전 현재 값을 먼저 읽어요)

## 8. 차량·내비 신호 표 (2026-11-05 에뮬 실측)

이 표가 권한 신청 목록이에요(AC-N-7). Vehicle SDK 퍼미션은 App Market과 사전 협의·승인된 것만 선언할 수 있고, 미승인은 심사 탈락이에요. 같은 이름이 두 곳에 있어서 접두어를 붙여 적었어요: **P** = `pleos.car.permission.*`, **A** = `android.car.permission.*`.

| 값 | API | 단위 | 권한 | 쓰는 곳 | 에뮬 |
| --- | --- | --- | --- | --- | --- |
| 주행가능거리 | AAOS `RANGE_REMAINING` (CarPropertyManager, 콜백 등록) | m | A `CAR_ENERGY` | F1·F2·F5 | 읽힘, 콘솔과 일치. SOC와 따로 움직임 |
| 배터리 용량 | AAOS `INFO_EV_BATTERY_CAPACITY` | Wh | A `CAR_INFO` | F1·F9 | 읽힘, 콘솔 용량(kWh) × 1000 |
| 연료 종류 | AAOS `INFO_FUEL_TYPE` | 코드 배열(10 = 전기) | A `CAR_INFO` | S1 자동 판별 | 읽힘 \[10\] |
| 탱크 용량 | AAOS `INFO_FUEL_CAPACITY` | mL | A `CAR_INFO` | F1(내연) | 15,000 고정 → 차종 표 |
| SOC | `EvBattery.getEvBatteryStateOfCharge` + 리스너 | % | P `CAR_ENERGY` | F1·F5·F9 | 읽힘 |
| 연료 잔량 | `Fuel.getFuelPercent` + 리스너 | % | P `CAR_ENERGY` | F1·F9 | 콘솔에 없음 → 모의 값 |
| 연비 | `Fuel.getCumulativeFuelEconomy` | L/100km | P `CAR_ENERGY` | F1·F10 | 값 없음 → 차종 표 |
| 전비 | `EvBattery.getCumulativeEvEfficiency` | km/kWh | P `CAR_ENERGY` | F1·F10 | 값 없음 → 차종 표 |
| 충전 스위치 | `EvBattery.getEvChargeSwitchState` + 리스너 | on/off | P `CAR_ENERGY` | F9 | 읽힘 |
| 누적 주행거리 | `Odometer.getCurrentDistanceDriven` | km | P `CAR_DRIVE` | F10·F17 | 읽힘, 콘솔로 올리기만. AAOS `PERF_ODOMETER`는 A `CAR_MILEAGE` 부여 불가라 금지 |

| 현재 위치 | NaviHelper `getCurrentLocationInfo` (대안 FusedLocation SDK) | 위경도 | P `NAVI_ROUTE` (FusedLocation은 P `FUSED_LOCATION`) | F5 origin | 읽힘, 성남 수정구 시흥동 |

5. 차종 식별 방법(VIN invalid, `INFO_MAKE/MODEL` 비식별)
6. Lifestyle 카테고리 + `distractionOptimized` 미선언 시 기록·정산 기능이 범위 안인지, adb 설치본이 아닌 배포본의 DO 인정 경로
7. 팀 제작 고정 이미지(제작에 AI 도구 사용)의 AI 생성 콘텐츠 심사 대상 여부
