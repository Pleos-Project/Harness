# 노고 기능 명세서 v0.6 (운전 노고 정산)

Nov 7, 2026 · 작성 효성 · #46 3단계 · 11/9 고침(#62 정차, #63 시간대별 날씨, #68 도착, 명준 11/8 기획 결정, 중간 정산) · **11/14 v0.6**(노고 PRD v2.0: 내비 도착 신호, 주행 중 서비스, 알림으로 열기, 동의 단계, 운전석 문 뺌, 방식 B 숨김)

안드로이드·서버 담당이 이 문서만 보고 구현할 수 있게, 기능마다 트리거·입력·처리·출력·예외와 수용 기준(AC)을 적어요. 운전 노고 정산 PRD v1.1을 기준으로 **처음부터 새로 썼어요.** 기능명세서 v0.4(잔고 → 한 장 → 출발 흐름)는 이 문서로 대체되고 더 참조하지 않아요. **v0.6은 노고 PRD v2.0에 맞춰 고친 판이에요.** 바뀐 곳은 18절에 모았고, v0.5는 `docs/archive/`에 있어요. 제품 이름은 노고로 확정했고 코드 식별자(`chagok`, `cg-`)는 그대로예요. 본문에 남은 "차곡"은 같은 앱을 가리켜요.

## 2. 공통 규칙과 비기능

| 항목 | 규칙 | 수용 기준 |
| --- | --- | --- |
| 정차·주행 상태 | 기어 P이고 `CarUxRestrictionsManager` 규제가 없으면 정차, 그 밖은 주행이에요. 정차에서만 상호작용해요. 주행으로 바뀌면 모든 화면을 즉시 숨기고 상태를 저장해요 | AC-C-1: 콘솔 `driving_regulation on` 1초 안에 UI 숨김, `off`면 직전 화면 복귀 |
| 데이터 읽기 시점 | 앱 실행·화면 진입·사용자 조작 때 읽어요. 화면이 보이는 동안의 변화만 리스너로 받아요(기어, 착석, 내비 콜백). 화면이 가려지면 화면 쪽 리스너를 모두 해제해요. **예외는 주행 중 포그라운드 서비스 하나예요**: 실제 출발부터 도착(또는 그만두기)까지 내비 이벤트 4개(안내 시작·목적지 도착·안내 종료·경유지 변경 `onWaypointChanged`)만 받아요(F22, 11/12 팀 합의, DECISIONS 11/14 '주행 중 경유지 변경'). 타이머 반복 읽기와 폴링은 없어요. 정차는 도착 때 한 번 묻기만 해요(F21, 자동 측정 없음 #62). 내비와 나란히 띄워 차곡이 살아 있을 때 더 받는 건 정체 구간 목록(F20 ②)뿐이에요 | AC-C-2: 백그라운드 전환 뒤 SDK·AAOS 호출·콜백 로그 0건. 주행 중 서비스가 받는 내비 이벤트는 예외이고, 서비스도 폴링·타이머는 0건 |
| 계산 위치 | 노고·금액·제안은 앱 로컬(`engine` 패키지)에서 계산해요. 서버 호출은 날씨(`GET /v1/weather`, 도착 때 `GET /v1/weather/trip`)와 출발 화면 목적지 검색 `GET /v1/places`뿐이에요 | AC-C-3: 네트워크를 끊어도 출발·영수증·제안·기록이 떠요(날씨는 '정보 없음') |
| 숫자 표기 | 아래 '노고 표기' 표 | AC-C-4: 금액·배수·% 전수 검사 |
| 날씨 실패 | 타임아웃 3초. 도착 때 시간대별 조회(`/v1/weather/trip`)만 4초예요(서버가 기상청 호출을 3초에서 끊어서, June #66·효성 11/8). 시간대별 조회가 실패하면 출발·도착 1회 관측(절반씩, F23)으로 가고, 그것도 실패하면 그 지점 날씨를 '정보 없음'(가산 0)으로 두고 진행해요 | AC-C-6: 서버를 내려도 출발·도착이 막히지 않아요 |
| 시연 값 표기 | 데모 고정 모드(12절)는 설정 스위치 설명으로만 알려요("켜면 시연용 값(태안 꽃지해수욕장 · 1.57배)으로 고정해요"). 화면 구석의 "시연용 값" 알약은 뺐어요(DECISIONS 11/13) | AC-C-7 |
| 금지 문구 | ① 순위·비교("다른 운전자보다") ② 운전 실력·습관 평가 ③ "아꼈어요" ④ **운송 대가 표현**("운임", "운송비", "대가", "요금", "청구") ⑤ **동등 주장**("○시간어치", "○시간 운전한 것과 같은") ⑥ 재촉("아직 안 보냈어요" 등) ⑦ 금액을 값 매기듯 말하는 표현("고마움의 기준", "돈으로 치면", "적당해요") | AC-C-8: 문구 전수 검사 0건(`lint_copy.py`) |
| 표현 원칙 | 금액 화면 문구는 노고 PRD v2.0 7-7을 따라요: 큰 숫자 "한 사람 약 ○천 원", 근거 "운전 노고 약 ○만 ○천 원을 운전자 포함 n명이 나눈 값 · 최저임금 1분 178원 기준". 머리 줄("오늘 운전을 챙긴다면")은 두지 않아요(명준 11/14, 디자인 v191). 강제가 아니라는 건 [운전자 챙겨주기]를 누른 뒤에만 금액이 나오는 순서와 [좋아요] · [닫기]가 말해요. 평가가 아니라 "오늘 이만큼 운전했다"는 말투예요. **화면 문구는 모두 임시예요.** 확정 문구(근거 한 줄·출발 화면 미리보기 포함)는 명준이 디자인하며 넘겨주고, 그 전까지 다른 사람은 문구를 고치지 않아요. 엔진·앱은 상수만 바꾸면 되게 둬요(명준 #60) | AC-C-12: 화면 문구 검토 |
| 레이아웃 | 가로·세로·멀티 윈도우, 최소 글자 12sp, 레터박스 없음 | AC-C-9: 세 레이아웃 스크린샷 |
| 실행·복귀 | 10초 안에 첫 화면이 떠요. 다른 앱에서 돌아오면 직전 화면을 복원하고, 열린 출발 기록도 앱을 재시작한 뒤 유지돼요 | AC-C-11 |
| 로그 | 기능별 1줄 JSON. 좌표·목적지 이름·VIN은 남기지 않아요 | AC-C-10 |

**노고 표기** `[제안]`

| 값 | 표기 | 예 |
| --- | --- | --- |
| 운전 시간 | 분 단위 반올림, "○시간 ○분" | 2시간 10분 |
| 부담 배수 | 소수 둘째 자리 반올림 + "배". 1.00이면 "평소 같은 길"(DECISIONS 11/9 시안 v104) | 평소보다 1.57배 힘든 길 |
| 줄별 가산 | 정수 % 반올림. 어림이 0이면 "+1% 미만" | +40%, +1% 미만 |
| 금액 | 원 단위까지 계산한 뒤 마지막에 천 원 단위 반올림. 어림이 0이면 "1천 원 미만" | 약 3만 6천 원 |
| 1인 몫 | 어림하기 전 총액을 n으로 나눈 뒤 천 원 반올림 | 한 사람 약 9천 원 |
| 거리 | km 정수 | 104km |

- 반올림은 Python `round_half_up`, Kotlin `roundHalfUp`만 써요.
- 곱하고 나누는 순서는 엔진 두 벌에서 같게 해요.

| 항목 | 요구 | 수용 기준 |
| --- | --- | --- |
| 실행 | 콜드 스타트 10초 안에 홈 | AC-N-1 |
| 상태 복원 | 주행 전환·멀티태스킹에서 돌아오면 직전 화면 복원 | AC-N-2 |

GPS 궤적은 없어요. **현재 위치로 도착을 판정하지 않고, 목적지 좌표는 기기에 남기지 않아요**(PRD v2.0 11장). 서버는 좌표를 저장·캐시·로그하지 않아요 | AC-N-4: 끝난 기록·로그·서버에 좌표 없음 |
| 성능 | 주행 중 화면 없음. 주행 중 서비스는 내비 이벤트만 받고 폴링·타이머가 없어요. RAM 400MB 이하 | AC-N-5 |
| 광고·알림 | 광고 없음. 사용자에게 보이는 시스템 알림은 도착 확인 알림 한 번뿐이에요(F22). 주행 중 서비스의 상주 알림은 Pleos가 화면에 보여 주지 않는 카테고리(`service`)로 둬요(`navigation`이면 팝업이 내비 회전 안내 자리를 덮어요, June 11/12 실측). 재촉하는 알림은 없어요 | AC-N-6 |
| 퍼미션 | 매니페스트 = `contract/permissions.md`(11절) | AC-N-7 |

## 3. 화면 전이

```
홈 ─[동승 출발]→ 출발 화면(목적지 검색·최근 목적지·즐겨찾기, 인원 확인 알림, requestTrip으로 ETA·정체 선취득) ─[안내 시작]→ 내비 안내(앱 가려짐, 주행 중 서비스가 내비 이벤트만 받음)
                                                        │
   가는 중에 앱을 열면 홈: [도착했어요] · [멈추기] · 중간 정산(F27)
   내비 도착 신호 → 도착 확인 알림 한 번(앱은 스스로 앞으로 오지 않음) → 알림을 누르거나 앱을 엶(기어 P)
        도착 → ① 오늘 운전 돌아보기(조건 다섯 줄을 약 10초 동안 셈, 다 세면 [운전자 챙겨주기]·[다음에])(F29)
               → [운전자 챙겨주기]: 쉰 시간 시트(먼저 묻는다) → ② 영수증 + ③ 제안 A 한 화면(고른 답으로 센 값. 영수증의 쉰 시간 값을 눌러 바꾸면 줄 값 다시 계산) → 선택 → 홈
               → [다음에]: 영수증·금액 없이 기록만 남기고 홈
        도착 상한을 넘으면(F22) → 영수증 대신 "정리하지 못함" → [홈으로]
```

- **오늘 운전 돌아보기** `[디자인]`: 계산 연출과 동의 단계를 한 화면으로 합쳤어요(명준 11/14, 아티팩트 '도착 · 오늘 운전 돌아보기'). 머리말 "○○에 도착했어요"(아래 줄은 세는 동안 노고 문구, 다 세면 "오늘 운전 2시간 10분 · 4명"), 왼쪽 노고 캐릭터, 오른쪽 조건 다섯 줄을 약 10초 동안 하나씩 세요. 금액·배수는 없어요. 세는 동안 [건너뛰기]가 있어요. 옛 계산 연출(원 6개, 약 13초, 디자인 Q-2026-11-07-06)은 쓰지 않아요. 화면은 `design/screens/review.html`, 움직임은 `design/HANDOFF_v4.md` 6절이에요.

- **동의 단계**(F29): 다 세면 [운전자 챙겨주기]·[다음에]가 켜져요. [운전자 챙겨주기]를 누른 뒤에만 영수증과 금액이 나와요.

## 5. F21 정차 빼기 (#58·#62)

June 실측(#51, 11/7)에 따르면 기본 배치에서는 [안내 시작] 뒤 1초 안에 순정 내비가 차곡을 덮어 `onStop`되고 약 11초 뒤 동결돼요. 그래서 주행 중 신호를 받을 수 없고, **도착 뒤 "중간에 쉰 시간"을 한 번 묻는 게 기본**이에요(#58, 명준 결정). 도착에서는 [운전자 챙겨주기]를 누른 뒤 **영수증보다 먼저** 하단 시트로 묻고, 고른 답으로 센 영수증을 내요. 중간 정산(F27)은 지금 앱대로 영수증을 먼저 내고 시트를 늦게 올려요(DECISIONS 11/15 '쉰 시간을 묻는 순서'). 영수증의 "중간에 쉰 시간" 값을 눌러 답을 바꾸면 줄 값을 다시 계산해요(디자인 Q-2026-11-07-06). 가볍게 끝나는 시트·칩이고, 모양은 디자인에서 정해요.

| 항목 | 명세 |

| 기본: 도착 뒤 한 번 묻기 | 영수증 화면 안에서 "중간에 쉰 시간"을 한 번 물어요: 없음 / 15분 / 30분 / 1시간 이상 → 0 / 15 / 30 / 60분. 운전 시간 T = 경과 시간 − 답. 고르기 전에는 아무 칩도 골라 두지 않고, 영수증 자리에 "오늘 운전을 정리하는 중이에요", 제안 자리에 "확인 중"만 보여요(DECISIONS 11/13, #148). 도착에서는 [운전자 챙겨주기]를 누른 뒤 영수증보다 먼저 묻고, 고른 답으로 센 영수증을 내요(DECISIONS 11/15 '쉰 시간을 묻는 순서'). 중간 정산(F27)도 같은 시트로 물어요. 다만 지금 앱의 중간 정산은 영수증을 먼저 내고 시트를 늦게 올려요(같은 11/15 줄) |

| 경유지·정차 | 경유지 도착(`onWayPointArrived`)은 듣지 않아요. 휴게소·신호 대기의 기어 P는 정차예요. **주행 중에 경유지를 넣거나 바꾸면** `onRouteCancelled`가 온 뒤 약 9초에 `onWaypointChanged`가 와요(`onRouteStarted`는 오지 않음, June 에뮬 실측 11/14 #145). 이때는 새 안내 시작처럼 "안내 종료" 기억과 도착 확인 알림을 지우고, 떠 있던 "도착했나요?" 질문도 닫아요. 출발 기록은 다시 잡지 않아요: 함께 오는 `name`이 경유지 이름이라 목적지 변경으로 읽으면 안 돼요(앱 #153) |
| 목적지 변경 | 주행 중 내비에서 목적지를 바꾸면 이전 안내의 `onRouteCancelled`가 오고 약 7.5초 뒤 새 안내의 `onRouteStarted`가 와요(June 에뮬 실측 11/13·11/14). 새 안내가 시작되면 "안내 종료" 기억과 알림을 지우고 같은 주행을 이어 가요. 새 `RouteStartInfo`의 `name`이 출발 기록의 `dest_name`과 **다를 때만** 출발 기록을 다시 잡아요: `dest_name` = 새 `name`, `eta_s` = (변경 시각 − 출발 시각) + 새 `duration`(초). `route_m`과 정체 값은 출발 때 값 그대로 둬요 `[제안]`. 이름이 같으면(첫 안내, [아직이에요] 뒤 재안내, 같은 목적지로 다시 안내) 다시 잡지 않아요: 그때 다시 잡으면 늦어진 시간이 기준에 흡수돼 "예상보다 더" 줄이 사라져요(June #152). 서비스가 받은 새 값(이름·`duration`·받은 시각)은 안내 끝처럼 기기에 남기고 앱이 보일 때 출발 기록에 반영해요. 상주 알림 제목의 목적지 이름도 같이 바꿔요. `distance`는 m이고 km 단위로 반올림돼 오는 것으로 보여요 |
| 가정 | 실차에서 목적지에 닿으면 내비가 `onDestinationArrived`를 보낸다고 가정해요. 에뮬은 차가 움직이지 않아 신호를 넣어 확인했고(#146), 실제 신호는 실차 확인이에요. 틀려도 ③④로 끝낼 수 있어요 |

| 처리 | `arrived_at`을 기록하고, 날씨는 `GET /v1/weather/trip`과 `GET /v1/weather`(도착 좌표)를 같이 부르고 trip이 실패하면 1회 관측 값을 쓰고(F23), 출발 때 계산해 둔 일몰·일출을 써요. 계산은 기어 P에서 시작해요. 오늘 운전 돌아보기(F29)를 보여 주고, [운전자 챙겨주기]면 영수증(F23)이에요. 쉰 시간은 영수증보다 먼저 하단 시트로 묻고, 고르기 전에는 "오늘 운전을 정리하는 중이에요"만 보여요(F21). 정리하지 못함이면 영수증 대신 안내 + [홈으로]예요(모양은 디자인). 기록은 남겨요: `choice = "unsettled"`, 영수증·제안 없이 목록·카드에 "정리하지 못함"(명준 #75, 앱 #100) |
| 예외 | 열린 출발 기록이 없으면 무시해요. 고르기 전에 앱을 나가면 다시 열 때 그 주행의 돌아보기 화면(다 센 상태)부터 이어지고, 조건을 세는 연출은 다시 보지 않아요. 홈의 "도착" 표시 상태는 뺐어요(DECISIONS 11/14 '고르기 전에 나간 도착', 디자인 v191) |

## 15. 추후 도입 고려

- **퇴근 후·시간대 피로**: 졸음 사고는 2시·6시·16시 무렵에 몰려요(Horne·Reyner 1995). 다만 운전 부담 수치가 없어요.
- **가산율 보정**: 설문이나 실사용 데이터로 보정해요.
- **위치로 도착 보조 판정**: 도착 신호를 못 받았을 때 현재 위치와 목적지 사이 거리로 판정하려면 목적지 좌표를 주행 중 기기에 둬야 해요. 1차에서는 넣지 않아요(PRD v2.0).
- **시동을 켤 때 서비스 다시 띄우기**(`RECEIVE_BOOT_COMPLETED`), **쉰 시간 미리 채우기**: 1차에서는 넣지 않아요(#145).
- **방식 B(관례로 챙기기)**: 1차 화면에서 숨겼어요(F25, PRD v2.0 9장).
- **차 트립 주행 시간**: 쓸 수 있으면 실제로 달린 시간으로 운전 시간을 바꿀 수 있어요.
- **숙박 여행의 공동 경비 1인분**: 국민여행조사 숙박여행 1회 22만 1천 원.
