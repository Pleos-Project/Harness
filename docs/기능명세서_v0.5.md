## 2. 공통 규칙과 비기능

| 항목 | 규칙 | 수용 기준 |
| --- | --- | --- |
| 정차·주행 상태 | 기어 P이고 `CarUxRestrictionsManager` 규제가 없으면 정차, 그 밖은 주행이에요. 정차에서만 상호작용해요. 주행으로 바뀌면 모든 화면을 즉시 숨기고 상태를 저장해요 | AC-C-1: 콘솔 `driving_regulation on` 1초 안에 UI 숨김, `off`면 직전 화면 복귀 |

| 시연 값 표기 | 데모 고정 모드(12절)에서는 "시연용 값"을 고정으로 표시해요 | AC-C-7 |

| 값 | 표기 | 예 |

## 3. 화면 전이

```
홈 ─[동승 출발]→ 출발 화면(목적지 검색·최근 목적지, 인원 확인 알림, requestTrip으로 ETA·정체 선취득) ─[출발]→ 내비 안내(앱 가려짐, 주행 중 동작 없음)
                                                        │
   가는 중에 앱을 열면 홈: [도착했어요] · [그만두기] · 중간 정산(F27)
        도착 → ⓪ 계산 연출(매번, [건너뛰기]) → ① 영수증 + ② 제안(A 또는 B) 한 화면(쉰 시간은 영수증이 나온 뒤 하단 시트, 답하면 줄 값 다시 계산) → 선택 → 홈
        도착 상한을 넘으면(F22) → 영수증 대신 "정리하지 못함" → [홈으로]
```

- **계산 연출** `[디자인]`: 도착하면 매번 약 13초 동안 계산 연출이 나와요(2D 차는 공용 세단 1종). [건너뛰기]를 누르면 바로 영수증으로 가요(명준 결정, 디자인 Q-2026-11-07-06).

- **앰비언트 라이트**: 차곡 화면이 보이는 동안(정차) 차의 앰비언트 라이트를 브랜드 색 `#D9F77A`로 켜 두고, 주행으로 바뀌거나 가려지면 되돌려요(F28, 11/9 합의). 주행 중에는 켜 두지 않아요.

- **홈** `[제안]`: [동승 출발] 버튼, 진행 중인 출발이 있으면 [도착했어요]·[그만두기](F27), 최근 기록 3건을 보여 줘요. 기록 목록·상세는 1차에 넣어요(명준 Q-08-01, F26). 영수증과 제안은 한 화면이에요(Design v2 #75·#76).
- **나눠 낼 인원이 1명**이거나 운전자 몫이 커피 1인분의 절반보다 작으면 A·B 모두 제안 없이 기록만 남겨요(F24·F25, 명준 Q-07-04).

## 4. F20 동승 출발

| 항목 | 명세 |
| --- | --- |
| 트리거 | 출발 화면에서 [출발] (기어 P) |
| 입력 | 목적지: 서버 `GET /v1/places?query=`(카카오 로컬 키워드 검색 대행)로 찾거나, `NaviHelper.getRecentDestinationInfo`의 최근 목적지에서 골라요. 지도에서 찍기는 1차 제외예요. NaviHelper에 검색 API가 있으면 그걸 우선해요 `[June 확인]`. 나눠 낼 인원 n: 착석 센서(P `CAR_SEATS`)로 감지한 뒤 **인원 확인 알림**(PR #34·#40, "3명이 탔어요 · 나눠 낼 인원을 맞춰 주세요" −/+ [확인] [닫기])을 출발 화면에서 다시 써요. 현재 위치: `NaviHelper`. 날씨 조회용 반올림 값만 출발 기록에 두고 도착 조회 뒤 지워요(AC-N-4) |
| 처리 | ① `requestRoute(목적지)` → `onRouteStarted(RouteStartInfo)`: `duration`(ETA 초), `distance`(m)를 저장해요. ② `getRouteStateInfo` → `onRouteStateInfo` → `trafficStatus.congestionItemList`: **목록이 채워진 응답**일 때 SLOW·HEAVY 구간의 `distance` 합(m)과 **구간마다 `distance ÷ avrSpeed` 합**(초)을 저장해요. `trafficCongestionTime`은 분 단위로 올린 값이라(짧은 구간도 최소 60초) 합이 약 1.75배 부풀어서 쓰지 않아요(June 실측). 첫 응답은 0개라, 재조회는 앱이 보이는 동안 최대 2회만 해요(폴링 없음). ③ `GET /v1/weather`(출발 좌표) → 강수 형태(시간대별 조회가 실패할 때의 대체용, F23). ④ 출발 기록을 저장해요. 차 트립 주행 시간은 1차에서 쓰지 않아요(#68) |
| 출발 기록 | `{trip_id, departed_at, eta_s, route_m, congestion_ratio, congestion_m, congestion_s?, n, dest_name, weather_dep, sunrise, sunset, dep_lat?, dep_lng?}` (`congestion_s`는 구간 목록을 받았을 때만. `dep_lat`·`dep_lng`는 반올림 좌표로 도착 조회 뒤 지움) |

**수식** (#47)

```
엔진 입력의 정차는 도착 때 답한 쉰 시간 Q(0·15·30·60분) 하나예요(F21, #62)

경과 E       = 도착 시각 − 출발 시각(분)
T            = E − Q
피로 구간    = 중간 정산(F27) 시각이 있으면 [출발, 정산1], …, [정산k, 도착]의 벽시계 길이 × (T ÷ E)
               없으면 Q ≥ 15일 때 [T/2, T/2], 아니면 [T]
정체 분 C    = 기본: 정체 비율 × T                   ※ 출발 전 requestTrip의 비율(효성 결정, 열린 결정 28)
               구간 목록이 있으면: min(congestion_s ÷ 60, T)  ※ congestion_s = Σ 구간 distance ÷ avrSpeed
지연 분 D    = max(0, T − eta_s ÷ 60), 단 D < 0.10 × (eta_s ÷ 60)이면 0
밤 분 N      = [출발, 도착]과 밤이 겹친 분 × (T ÷ E)
비·눈 분     = 시간대별 관측이 있으면(#63): 1시간 조각 [H, H+1)마다 조각 가운데(H:30)가 경과의 가운데
               (출발 + E ÷ 2)보다 앞이면(같으면 앞) 출발 지점, 뒤면 도착 지점 관측으로 판정하고,
               [출발, 도착]과 겹친 분을 비·눈별로 더한 뒤 × (T ÷ E). unknown 조각은 0
               없거나 겹친 조각이 모두 unknown이면: T의 앞 절반은 weather_dep, 뒤 절반은 weather_arr
               → 비 분 R, 눈 분 S
피로 F       = Σ 피로 구간마다 max(0, 구간 − 120) × 0.125
노고(분)     = T + 0.27·C + 0.27·D + 0.04·N + 0.40·R + 0.49·S + F
부담 배수    = 노고 ÷ T
줄별 가산(%) = 그 항의 가산 ÷ T × 100
```
