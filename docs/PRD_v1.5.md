## 0. 한 페이지 요약
- **한 줄 정의:** 차곡은 **지금 차에 든 돈(연료·배터리 잔고)에서 출발해, 차가 갈 만한 한 곳을 이유와 함께 골라 주고, 다녀온 이동비를 시키지 않아도 쌓아 주는** 차량 앱이다.
- **PT 한 문장:** "말하지 않아도 필요한 것을 돕는 AI(박민우 대표, 아시아투데이 2026-05-21)와 같은 방향을, 서드파티 SDK로 먼저 만들었습니다." `[원문 인용은 AI 엔지니어 제공, 팀 원문 확인 필요]`
- **배경 질문:** "이 돈으로 어디까지 갈 수 있지?"
- **핵심 통찰:** 운전하며 쓰는 돈(기름·충전·통행료·주차)은 계획대로 쓰이지 않고 **그냥 흘러나간다.** 차곡은 이 돈을 아끼라고 다그치지 않는다. 대신 **"이 안이면 괜찮다"는 경계**로 바꿔 떠날 곳을 정하게 하고, 흘러나간 돈을 다녀온 곳과 함께 보여 준다.
- **돈의 역할:** 목적지를 고르는 "기준"이 아니라 **경계(안전망)와 기록**. 카드의 주인공은 테마·시간이고 금액은 배지다.
- **메인 사용자:** 자기 차로 주말·당일 근교를 떠나는 사람. 국내 여행은 **자가용 84.5% · 주말 61.7% · 당일 58.8% · 사전예약 35.4%**(2025 국민여행조사).
- **차곡이 하는 3가지**
  1. **지금 차에 든 것에서 출발한다:** 잔고(원·km), 탄 사람 수, 마지막 목적지
  2. **차가 한 장을 고르고 이유를 한 줄로 말한다:** "추가 0원 안 · 75분 안 · 지난번과 다른 테마"
  3. **시키지 않아도 쌓인다:** 순정 내비로 간 이동까지 다음 시동 때 "지난번 이후 · 약 얼마 · 어디"로 정리

## 1. 아이디어 개요

### 1-1. 기획 배경 (기획서용 문단, 각주는 14장)
> 우리 국민은 한 해 평균 6.5번 국내 여행을 떠나고, 그중 84.5%가 자가용을 이용합니다.¹ 여행의 61.7%는 주말에, 58.8%는 당일치기로 이루어지며, 사전예약을 하는 여행은 35.4%에 그칩니다.¹ 여행지에서 쓰는 돈 가운데 교통비는 21.3%로 음식점비 다음으로 큰 몫을 차지합니다.¹ 2026년 5월에는 휘발유 값이 리터당 2,011원까지 올랐고,² 여름휴가 비용이 부담된다는 응답이 45.7%였습니다.³ 그런데 운전하며 나가는 돈은 주유·충전·통행료로 흩어져 한 번도 합산되지 않습니다. 차곡은 차가 이미 알고 있는 잔고와 이동 기록으로 "이 돈으로 어디까지"에 답하고, 다녀온 이동비를 조용히 쌓아 둡니다.
- 유가는 5월 정점 이후 하락 중이다(10월 기준 21주 연속 하락, 머니투데이방송 2026-10-10). "기름값 2천 원 시대" 같은 과장은 쓰지 않는다.

### 1-3. "돈이 꼭 필요한가" 검사 (I18 유지)
| 상황 | 돈 입력 | 거리로 바꾸면 | 돈이 필요한가 |
|---|---|---|---|
| 내연, 혼자, 국도 | 3만 원 | 120km 안 | 아니다 |
| 유료도로 많은 지역 | 3만 원 | 120km 안 | 조금(통행료) |
| 전기차 집 충전 | 1만 원 | 150km 안 | **그렇다**(kWh당 60원대~340원대, C1 E4) |
| 탱크에 이미 반 | 추가 0원 | 표현 불가 | **그렇다** |
| 넷이 동승 | 총 4만 원 | 170km 안 | **그렇다**(1인 몫) |

- **설계 원칙**
  1. 돈은 입력이 아니라 차가 먼저 보여 주는 값(잔고)이다.
  2. 사용자가 더하는 돈은 선택지 3개(0원 / +1만 / +3만)로만 받는다.
  3. 대표 장면은 돈이 결과를 바꾸는 장면(추가 0원, EV 단가, 1인 몫)으로 한다.
  4. **정확도로 경쟁하지 않는다.** 숫자는 어림으로, 정확한 0만 지킨다(C9·C10).

## 2. 문제 정의와 근거

### 2-1. 사용자 문제 (C1 VOC 67건 · C2 · C3)
| 문제 | 대표 근거 | 신뢰도 | 차곡 |
|---|---|---|---|
| **어디 갈지 정하지 못함**(가장 많고 날것인 페인) | "가긴 가고 싶은데 어딜 가야할지 모르겠어요"(82쿡 2025-10), "아는 곳이 여기뿐… 수없이 갔어서" | C(커뮤니티, 원문 확인) | 차가 한 장을 골라 줌 |
| 비용 때문에 근교도 줄임 | "당분간 근교 여행도 줄일 수밖에 없을 것"(머니투데이 2026-04), 비용 절감 1순위 "먼 곳 대신 가까운 곳" 36.5%(피앰아이) | B | "추가 0원" 범위 |
| 동승 비용 꺼내기 어색 | "돈 얘기는 서로 먼저 꺼내기 어렵고요"(클리앙 2026-10, 모다닥 개발자) · 평균 동반자 3.7명 | C · A | 1인 몫 숫자(정산·송금 안 함) |
| EV는 충전 장소마다 돈이 다름 | "아파트 314원 vs 부모님댁 새벽 60원대"(클리앙 2026-08) | C | 내 단가 기준 잔고 |
| 돈보다 운전 피로 | "운전하면 힘들다고 하니까 멀리 가자고도 못 하겠어"(블라인드 2024-11) · 편도 75분 넘으면 수요 급감(권영현·김의준 2015) | C · A | 카드에 시간 먼저, 75분 기준 |
| 이동비가 흩어져 합산 안 됨 | 하이패스처럼 자동 결제되면 덜 의식(Finkelstein 2009) · 명준 통찰 | A(논문) | 시동 시점 정산 기록 |

### 2-2. 알고 가는 약점 (숨기지 않음)
- **"이 예산으로 어디 갈 수 있나"를 직접 말한 VOC는 0건**(C1). 여행지 선택에서 지출은 4위, 1위는 환경이다(Lee 외 2022). → 돈은 경계 배지로만 쓴다.
- 차 여행에서 "얼마 썼는지 모르겠다" VOC도 0건(C1 영역 6). → 기록은 보조 기능이고, **일상 이동비 VOC는 추가 조사**(차계부 앱 리뷰).
- 범용 AI는 차·잔량·예산을 말해 주면 비슷한 목적지 목록을 준다(C8 실험). → 차곡은 정확도가 아니라 **입력 없음·한 장·자동 기록**으로 선다.
- 20대 목소리 부족(커뮤니티 차단, C1) → 인터뷰에 20대 포함.

### 2-3. HMW
- 어떻게 하면 주말 아침, 검색 없이 **갈 만한 한 곳을 차가 먼저 꺼내 줄** 수 있을까?
- 어떻게 하면 이미 넣은 기름·전기를 **"써도 되는 돈"으로 느끼게** 할 수 있을까?
- 어떻게 하면 **흘러나간 이동비를 기록 입력 없이** 다녀온 곳과 함께 보여 줄 수 있을까?

## 5. 핵심 기능

### 5-1. 기능 목록
| ID | 기능 | 설명 | 우선 |
|---|---|---|---|
| F1 | **잔고 카드** | 연료 %·SOC × 용량 × 연비(전비) × 단가 → "탱크에 3만 8천 원어치 · 약 420km". 단가 = 최근 주유·충전 단가 > 주변 평균 > 전국 평균 | MVP |
| F2 | **범위 설정** | 추가 0원 / +1만 / +3만, 당일·1박, 인원 자동 | MVP |
| F3 | **테마 경계** | 8개 중 0~2개(바다·호수·강·산·공원·도시·섬·드라이브길) | MVP |
| F5 | **차가 고른 한 장** | 점수 1위 카드가 앞면, 나머지는 뒤집힌 스택("다른 후보 3"). **교체 2회**(3회째는 "테마를 바꿔 볼까요?"로 범위 화면 안내, 11/5 확정). 교체 조작은 **스와이프 + 아이콘 버튼**(글자 "교체" 버튼 대신, 잠정) 앞면: 테마 일러스트 · 장소명 · 시간 · 금액 배지("추가 주유 없이 · 여유 50km" / "+1만 원 안팎" / "빠듯") · **이유 한 줄**(점수 상위 3개 근거 문장화). 탭하면 비용 분해(어림) | MVP |
| F8 | **내비 전달** | 1탭 → 순정 내비. 경유지 최대 2개(사용자가 고른 곳만, 추천 안 함) | MVP |
| F9 | **충전·주유 직후 카드** | EV: SOC 증가분 × 단가로 금액 추정 → 바로 장소 한 장. 내연: 금액 확인(3만 / 5만 / 가득 + 1만 원 단위 +/− 조정, 키보드 없음) → 한 장 | MVP |
| F10 | **시동 시점 정산 기록** | 앱 실행 시 직전 정산 이후 **주행거리 차 × 연비(전비) × 단가**, 1인 몫(직전 정산 때 저장한 착석 수), 마지막 목적지(`getRecentDestinationInfo`) → "지난번 이후 132km · 약 1만 8천 원 · 마지막 목적지 양평". 백그라운드 수집 없음. 순정 내비로 간 이동도 포함 | MVP |

### 5-2. 하지 않는 것
- **"글레오는 못 한다" 류의 비교 주장**(기획서·PT·화면 전부)
- 정확도 자랑("예상 vs 실제 맞춤" 표시)
- 주행 중 비용 미터·운전 점수
- "무게 감지" 등 확인되지 않은 센서 방식 서술(→ "좌석 센서로 감지")
- 인원 확인을 위한 온보딩·스플래시 화면
- 카페·맛집·여행 일정 추천(지도·글레오가 함) → 테마 필터만
- 백그라운드 센서 수집·폴링(가이드 위반)
- 송금·정산, 실행 중 AI 이미지 생성, 예산 → 최적 경로
- 주행거리·착석·잔량을 서버로 보내는 계산(잔고·범위·정산은 차 앱 로컬)

### 5-3. 숫자 표기 규칙
| 값 | 표기 | 이유 |
|---|---|---|
| 잔고 | 천 원 단위 "3만 8천 원어치" | 차가 아는 값, 기준점 |
| 카드 비용 | 5천 원 단위 어림 "3만 원 안팎" | 정확한 숫자는 약속으로 읽힘(Dietvorst 외 2015) |
| 추가 0원 | **"추가 주유 없이 · 여유 50km"** (정확한 0, 안전 여유 명시) | 0원 효과는 정확한 0에서만(Shampanier 외 2007) |
| 경계 카드 | **"빠듯"만** 표시("추가 주유 없이"와 함께 쓰지 않음). 엔진 기준: 왕복 거리가 (잔고 거리 − 안전 여유)의 90~100% | 경계에서 0원을 약속하지 않음 |
| 1인 몫 | 천 원 단위 어림 "1인 7천 원 안팎", **나눠 낼 인원** 1이면 표시 안 함. 토스트에서 확인 전에는 감지 인원으로 계산 | 카드 비용과 같은 어림 원칙 |
| 기록·정산 | 천 원 단위 "약 1만 8천 원"(기획서·숏폼 투싼 하이브리드 기준). PT(전기차)는 같은 수식으로 "약 8천 원" | 보장 아닌 기록 |
| 0원 어림 | 어림 결과가 0이면 "5천 원 미만"(1인 몫은 "1천 원 미만") | "0원 안팎" 방지 |
| 단가 없음 | 전국 평균으로 대체 + "평균 단가" 표기 | 엔진 문서 경계 케이스 |
| 시연 값 | 화면 구석 "시연용 값" | 에뮬 임의 값(명준 결정) |

### 5-4. 계산 규칙 (AI 엔지니어 · Android)
- **용량(실차):** 차종 식별(VIN / AAOS `INFO_MODEL`·`INFO_FUEL_TYPE` `[미확인]` / 설정 선택) → **파워트레인 단위 제원표**(공식 제원 직접 확인) → 주유 감지 자가 보정(F18). EV는 AAOS `INFO_EV_BATTERY_CAPACITY` `[Pleos 지원 미확인]` → 차종 표
- **용량·연료(에뮬):** 설정의 차종 표 + 모의 연료 %(임의 값)
- **계산 위치:** 잔고·범위·정산은 **차 앱 로컬**에서 계산한다. 수식의 기준은 엔진 문서 한 곳이고, 서버의 참조 구현과 fixture(D1~D6, 정산 10개)로 앱 결과를 대조한다. 같은 fixture를 앱 단위 테스트에도 넣는다.
- **잔고(km) 1순위 = 주행가능거리**(`Odometer.getRangeRemainingDistance`, m → km). 값이 없거나 0이면 잔량 × 용량 × 연비
  - 차가 주는 주행가능거리가 자체 예비분을 이미 뺀 값이면 안전 여유가 이중으로 빠진다 → 기술지원 7번 확인 전까지 안전 여유는 그대로 적용 `[미확인]`
  - 주행가능거리와 잔량 × 용량 × 연비가 30% 이상 차이 나면 로그로 남겨 연비 단위·용량 확인에 쓴다 `[제안]`
- **잔고(원) = 잔량 × 용량 × 단가.** 금액은 주행가능거리로 풀리지 않으므로 용량·단가 확인은 계속 필요하다
- 안전 여유 = max(50km, 잔고 km × 15%) `[가정, 인터뷰로 조정]`. 엔진 문서 8절 민감도 검증(실연비 편차·겨울 EV 전비 −25%) 결과에 따라 15% → 20%로 올릴 수 있음(11/13 확정)
- 실연비 = 공인 연비 × 0.85 `[가정]`(사용자 확인 전 기본값)
- 범위 반경 ≈ (잔고 km − 안전 여유 + 추가 금액 ÷ 단가 × 연비) ÷ 2 ÷ 1.3 `[굴곡 계수 가정]`
- 후보 비용 = 2 × 편도 km ÷ 연비 × 단가 + 2 × 통행료 + 주차 → 5천 원 단위 어림
- **시동 시점 정산(F10)** = (현재 누적 주행거리 − 직전 정산 주행거리) ÷ 연비 × **직전 정산 시점의 단가**. 1인 몫 = ÷ 직전 정산 때 저장한 **나눠 낼 인원**(확인값, 없으면 착석 수). 정산할 때마다 주행거리·착석 수·나눠 낼 인원·단가·시각 저장
  - 주행거리 차이가 0이면 정산 카드 생략. 최근 목적지가 없으면 핀 없이 금액만
  - 월 이동비 누적(F17)은 **앱 로컬에서 정산 결과를 합산**(서버는 구간 정산만)
  - 경계 케이스 10개(중간 주유, 며칠 만에 열기, 착석 변화, 단가 결측, 경로 API 실패 등)는 엔진 문서 8절 fixture로 고정
  - 주행거리 기반이라 중간 주유에 영향 없음(잔량 차이 방식보다 안전)
  - 앱은 시동 때 자동 실행되지 않음 `[자동 실행 가능 여부 미확인]` → 실제로는 "앱을 열 때 정산". 며칠 안 열면 구간이 합쳐짐("지난번 이후 3일 · 412km")
  - 최근 목적지는 "설정한 곳"인지 "도착한 곳"인지, 시각 필드가 있는지 `[미확인]` → 문구는 "마지막 목적지"
- **점수 함수(F5):** 추가 비용 적합 + 75분 안 + 테마 일치 + 최근 방문·테마 중복 페널티 + 주차 정보 유무. 상위 3개 근거를 이유 한 줄로 출력

[앱 실행 · 기어 P]

[홈] 맨 위: (직전 정산 이후 주행이 있으면) 정산 카드 "지난번 이후 132km · 약 1만 8천 원 · 마지막 목적지 양평" (닫기 가능)

   └─ "조건 바꾸기" → [범위] 추가 0원 / +1만 / +3만 · 당일/1박 · 인원 자동 · 테마 0~2 → [한 장]

        이유: 추가 0원 안 · 75분 안 · 지난번과 다른 테마
   │   ├ 탭 → 비용 분해(연료 + 통행료 + 주차, 어림)
   │   └ 옆으로 밀기 또는 아이콘(2회) → 스택의 다음 카드 / 3번째 → "테마를 바꿔 볼까요?" 카드 → [범위]
   ▼
[출발] 1탭 → 순정 내비
   ▼
[주행] 차곡 숨김 (DO 인정 시 3줄만)
   ▼
[다음 실행] 정산 카드 → 기록 지도 핀 + 이달 이동비 누적

### 6-2. 보조 플로우
- **충전 직후(EV):** 충전 스위치 OFF → "방금 약 1만 4천 원어치 충전" → 한 장
- **주유 직후(내연):** 연료 % 3%p 이상 상승 → 금액 확인(3만 / 5만 / 가득, 1만 원 단위 +/−) → 한 장
- **동승(인원 확인):** 착석 2명 이상 + 지난번 확인값과 다름 → 화면 상단에 토스트 "3명이 탔어요 · 나눠 낼 인원 [−] 3 [+] [확인]"
  - [확인] → 확인한 인원으로 1인 몫 배지("1인 2천 원 안팎"). 다음 정산에도 이 값 사용
  - −/+로 줄이면 나눠 내는 사람만 반영(예: 가족 3명 탑승, 운전자 1명만 냄 → 1 → 1인 몫 숨김)
  - 닫기(×) → 감지 인원 그대로 사용, 같은 인원이면 다시 묻지 않음
  - 혼자(1명)일 때는 토스트 없음. 온보딩·스플래시로 묻지 않음
- **예외**
  - 잔고 < 안전 여유 등 추가 0원 후보 없음 → 홈 오늘의 한 곳이 +1만 원 기준으로 자동 전환, 카드 위 "추가 0원으로 갈 곳이 없어 +1만 원 기준이에요"(범위 화면에서도 같은 문구). +3만으로도 없으면 "가까운 곳만 볼 수 있어요"
  - 범위 안 후보 < 3곳 → 테마 해제 또는 +1만 제안
  - 주행 전환 → 즉시 숨김, 선택 저장
  - 위치 없음 → 최근 위치 + "위치 확인 중"

## 7. 기술 구조

### 7-1. 전체 구성
```
[차량 앱 · AAOS]                                    [차곡 서버]                      [외부 데이터]
 Pleos Vehicle SDK ──┐  잔고·범위·정산(로컬 계산)    POST /v1/cards, /cards/swap
 NaviHelper ─────────┼─► 월 이동비 합산(로컬)  ──────► ├ 후보지 캐시(일 1회)  ◄──────── TourAPI
 CarUxRestrictions ──┤   한 장 렌더링                  ├ 점수 함수 · 이유 문장 ◄─────── 경로 API(카카오/네이버)
 CarPropertyManager ─┘   로컬 기록(정산 이력)          ├ 어림 비용 추정기     ◄──────── 오피넷 · 주차장 표준데이터
                                                       └ (검증용) /v1/range · /v1/settle 참조 구현 + fixture
```
- 원칙: 차 신호는 차에서 계산, 외부 데이터는 서버 캐시. 앱이 서버로 보내는 것은 카드 요청(출발 좌표·반경·테마·인원·최근 방문)뿐이다. VIN·위치 이력은 서버에 저장하지 않는다.
- 서버가 없어도 홈·잔고·정산은 뜬다. 서버 실패 시 카드 자리에 "잠시 후 다시"
- **시동 시점 조회만 사용:** 주행거리·잔량·착석·최근 목적지를 앱 실행 때 한 번 읽는다(가이드 "백그라운드에서는 센서 수집·폴링·타이머를 멈춘다" 준수).

### 7-4. 추천 엔진 (AI 엔지니어)
1. 후보 풀: TourAPI 테마 매핑, 일 1회 캐시
2. 필터: 직선거리 × 1.3 ≤ 반경
3. **점수 함수 → 1위가 앞면, 2~4위가 스택.** 상위 3개 근거 → 이유 한 줄
4. 정밀 비용은 상위 후보만 경로 API → 어림 처리
