## 3. 움직임 — 시간 · 곡선 · 순서

CSS 값이 Compose로 그대로 옮겨진다.

| CSS | Compose |
|---|---|
| `cubic-bezier(a,b,c,d)` | `CubicBezierEasing(a, b, c, d)` (b · d가 1을 넘는 튀는 곡선도 됨) |
| `0.38s` | `tween(380, easing = …)` |
| `infinite alternate` | `rememberInfiniteTransition` + `infiniteRepeatable(…, RepeatMode.Reverse)` |
| `transform` · `opacity` | `Modifier.graphicsLayer { translationX/Y · scaleX/Y · rotationZ · alpha }` |

### 3-1. 계산 연출 (`calc`, 가장 중요)

체크포인트 6개를 차례로 들른다: 날씨 · 정체 구간 · 예상보다 더 · 밤길 · 장시간 · 거리.
- 가로 창: 왼 → 오
- 분할 창: 위 → 아래, 레일은 창 가운데

| 단계 | 시간 | 곡선 · 내용 |
|---|---|---|
| 시작 대기 | 0.5초 | 진행 줄 "오늘 운전의 노고를 하나씩 세어 볼게요" |
| ① 웅크림(처음 한 번만) | 0.26초 | 차 `scale(1.04, .88)` + 왼쪽 4px, `(.3,0,.3,1)`. 바퀴 회전 시작(0.3초에 한 바퀴, linear) |
| ② 배기 연기(처음 한 번만) | 0.1초에 생김 | 크기 0.05 → 1(0.62초 `(.2,.7,.3,1)`), 위 · 뒤로 −30 · −18 흐름(1.15초 `(.45,0,.55,1)`), 0.62초부터 0.5초 동안 투명해짐 `(.4,0,1,1)`. 뭉게뭉게 0.4초 반복. 1.3초에 제거 |
| ③ 튀어 나감(처음 한 번만) | 0.46초 | 차 이동 `(.3,1.3,.5,1)` + 몸통 `jolt`(늘었다 돌아옴). 연기는 0.46초 동안 차 꽁무니를 따라오다 남음 |
| ④ 다음 체크포인트로 이동 | 0.55초 | `(.45,0,.25,1)`. 이동 중 들썩 1.5px(0.32초 반복) · 바퀴 회전. 레일 채움도 같은 시간 · 곡선 |
| ⑤ 도착 → 원 채움 팝 | 0.38초 | `scale .55 → 1.2 → 1`, `(.175,.885,.32,1.275)`. 가산 0이면 회색 원 |
| ⑥ 항목 그래픽 | 1.75초 | 원 위 300 × 240 칸. 나타남 14% · 유지 · 80%부터 사라짐(`cg-fx`). 값 글자는 0.25초 투명 + 0.35초 팝으로 올라옴 |
| ⑦ 다음 이동 시작 | 그래픽 1.4초 시점 | 그래픽이 사라지는 중에 차가 출발(겹쳐서 끊김 없음) → ④로 |
| ⑧ 마지막 | — | 차 두 번 통통(0.5초 × 2, 14px) · 합계 팝(0.35초 투명 + 0.5초 튐) · 진행 줄 "다 셌어요. 오늘 운전 정말 수고 많았어요" |
| ⑨ 영수증으로 | 1.9초 뒤 | 도착 화면 + 영수증 출력 |

- 전체 약 13초(항목당 약 1.95초).
- 진행 줄 문구는 체크포인트마다 바뀐다(문구는 `screens/calc.html`, 임시 문구).

### 3-3. Compose 예시 (계산 연출 뼈대)

```kotlin
val Pop = CubicBezierEasing(.175f, .885f, .32f, 1.275f)
val Move = CubicBezierEasing(.45f, 0f, .25f, 1f)
val Launch = CubicBezierEasing(.3f, 1.3f, .5f, 1f)

@Composable
fun CalcTrack(items: List<CalcItem>, onDone: () -> Unit) {
    val carX = remember { Animatable(-60f) }            // 가로 창 기준 px(= dp)
    var step by remember { mutableIntStateOf(-1) }
    LaunchedEffect(Unit) {
        delay(500)
        // 처음: 웅크림 0.26초 → 튀어 나감 0.46초(연기는 따로 0.1초에 시작)
        delay(260); carX.animateTo(0f, tween(460, easing = Launch))
        for (i in items.indices) {
            if (i > 0) carX.animateTo(i * gap, tween(550, easing = Move))
            step = i                                       // 원 채움 팝 380ms + 그래픽 1750ms 시작
            delay(1400)                                    // 그래픽이 사라지는 중에 다음 이동
        }
        // 마지막: 통통 2번 + 합계 팝, 1.9초 뒤 영수증
        delay(1900); onDone()
    }
    // step으로 원 · 그래픽 · 진행 줄을 그린다. 원 채움: animateFloatAsState(…, tween(380, easing = Pop))
}
```

## 4. 에뮬레이터에서 끊길 때 (빼지 말고 다듬기)

- **움직이는 건 `graphicsLayer`로만**(위치 · 크기 · 회전 · 투명도). `offset { }` 람다나 `padding`을 애니메이션하지 않는다. 레이아웃이 다시 돌면 끊긴다.
- 그래픽(구름 · 차 · 연기)은 `remember`로 한 번 만들어 둔다. 프레임마다 `Path` · `ImageVector`를 새로 만들지 않는다.
- 상태 읽기는 그리기 단계로 미룬다(`Modifier.drawBehind { }`, `graphicsLayer { }` 안에서 `value` 읽기). 그래야 재구성이 일어나지 않는다.
- 빗줄기 · 눈송이처럼 여러 개는 `Canvas` 하나에 같은 `InfiniteTransition` 값 하나로 위치를 계산해 그린다(개수만큼 컴포저블을 만들지 않음).
- 확인 순서
  1. 에뮬레이터 "GPU 렌더링 프로필"과 Layout Inspector의 재구성 횟수를 본다.
  2. 실제 차 화면(Connect-S)에서 다시 본다.
  3. 에뮬레이터만 느리면 AVD 그래픽을 Hardware로 둔다.
